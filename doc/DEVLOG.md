## 2026-10-03 — 修正翻譯頁裡的 Translate 選單、深淺切換改純圖示

**做了什麼**

- 修正:在翻譯頁裡點選單的 `English` / `日本語` 會出現 Google 的「Can't translate this page」。現在改成切換目標語言、留在同一頁
- 深淺切換按鈕拿掉「深色/淺色」文字,只留太陽/月亮圖示(滑鼠停留時有說明)

**為什麼**

- **錯誤的原因**:Google 的翻譯代理會改寫頁面上所有連結,選單那兩個指向 Google 翻譯的連結被改成「翻譯 Google 翻譯自己」。原本的程式在翻譯頁裡直接跳過不處理,所以連結是壞的。這是我上一輪沒有測到的情況(只測了從中文頁點過去)
- **拿掉文字**:那兩個字是用 CSS 加的,Google 翻不到,外國訪客會看到一個中文詞。使用者建議改純圖示,圖示不需要翻譯

**還沒做 / 下次要做**

- [ ] 這個修正同樣只能在線上的翻譯頁驗證,要使用者實際點一次(英文頁按「日本語」應該切到日文版的同一頁)

## 2026-10-03 — 翻譯頁導覽列改為跟著頁面走、手機版調整

**做了什麼**

- **翻譯頁的導覽列**:從「往下挪固定 56px」改成「不釘在視窗頂端,跟著頁面走」
- **手機文章頁的頂部**:高度改成跟著標題長。原本固定高度只放得下一行,兩三行的長標題(例如開發分享那篇)上半部會被導覽列蓋住
- **打字機效果只留在首頁副標題**:文章與其他頁面的標題直接顯示
- **手機展開的選單**:格子改成硬邊加邊框。主題原本是「8% 的白色」,在淺色模式的米色底上幾乎看不見
- **手機上的招牌光暈縮小**:光暈半徑原本有 26px 的下限,在手機上比招牌本身還大,整個招牌糊成一片;下限改為 14px
- DESIGN.md(第 3、6 節)、TECH.md 同步更新

**為什麼**

- **導覽列跟著頁面走**:固定挪 56px 有兩個問題——訪客把 Google 工具列縮成懸浮按鈕後會留下空隙;Google 改了工具列高度就又對不上。跟著頁面走則不必知道高度。代價是翻譯頁往下捲時導覽列會捲走,使用者已確認接受
- **關掉文章標題的打字機效果**:頂部高度改成跟著內容長之後,標題一個字一個字出現會邊打邊換行,整頁內容跟著往下跳。順便也讓標題一進頁面就讀得到
- **只對文章頁改高度**:用 `:has(.post-meta)` 挑出文章頁。其他頁面的標題都很短,維持固定高度比較整齊

**踩到的坑**

- 使用者看到翻譯頁的導覽列仍被蓋住,推測是快取:上線前先在本機點過 Translate,瀏覽器那時把翻譯網域上的舊樣式存了起來(已寫進 TECH.md)
- 我用 headless Chrome 對 Google 翻譯截了幾次圖,之後使用者的 IP 就被 Google 要求做機器人驗證。之後不再這樣做(已寫進 TECH.md)
- headless 截「打開的手機選單」會截到過場動畫的一半,看起來像選單是半透明的,其實不是。要先把 transition 關掉再點

**驗證了什麼**

- 截圖看過 390px 與 320px:首頁、兩篇文章、作品集、關於、封存、標籤、展開的選單(深淺各看過一部分,不是每頁都看了兩種模式)
- 長標題的文章在 320px 下三行標題完整顯示

**還沒做 / 下次要做**

- [ ] 翻譯頁的新做法**完全沒辦法由我驗證**,要使用者上線後用自己的瀏覽器(電腦與手機)看:導覽列是否在 Google 工具列下方、縮成懸浮按鈕後有沒有空隙、手機展開選單時最上面一排有沒有被工具列蓋住
- [ ] 仍然沒有在真實手機上測過觸控

## 2026-10-03 — 選單加上 Translate(Google 機器翻譯)、草稿進版控

> ✅ 使用者在本機看過後確認,已推上 main 並上線(2026-10-03)。

**做了什麼**

- 導覽選單最後加一個 `Translate` 下拉,提供 `English` 與 `日本語`。點下去用 Google 翻譯的網頁代理開啟訪客當下那一頁
- `na23.js` 新增 `setupTranslate()`:把選單連結的 `u=` 換成當下頁面的網址;偵測到自己正在翻譯代理裡時,在 `<html>` 加 `data-na-translated`
- `custom.css`:下拉選單改成實色硬邊(主題預設的半透明黑底在淺色導覽列上看不清楚);在翻譯代理裡把導覽列往下挪 56px,避開 Google 的工具列
- `source/_drafts/chiaoflow-doc-system.md` 進版控並推上 main,方便遠端接續寫
- DESIGN.md 第 1、3、8 節與 TECH.md 同步更新

**為什麼**

- **用連結而不是嵌入小工具**:Google 的 Website Translator 小工具早已不開放給新網站,而且要在每一頁載入第三方程式。翻譯代理只是一個連出去的連結,本站不載入任何 Google 的東西
- **不違反「不做中英雙語」**:那條指的是自己維護譯文。這裡是機器翻譯,本站不多維護任何內容;DESIGN.md 的措辭已改清楚
- **選單文字用 `Translate` / `English` / `日本語`**:看不懂中文的人才需要它,所以用他們看得懂的字
- **草稿放同一個公開 repo,不另開私人 repo**:草稿是將來會公開的文章大綱,沒有不能見人的內容;另開一個 repo 等於每次要在兩個地方同步,對剛接觸 git 的使用者是多出來的負擔。代價是別人在 GitHub 上讀得到草稿,且 git 歷史會永久保留——不想公開的東西不要寫進草稿

**踩到的坑**

- 主題的圖示字型沒有翻譯或地球的圖示,所以 `Translate` 沒有配圖示(寫了不存在的 class 只會靜靜地不顯示)
- 透過翻譯代理瀏覽時,Google 的工具列固定在最上面,會蓋住同樣固定在最上面的導覽列。上線前用線上的文章頁實測代理時發現的
- Bash 的 heredoc 內容含有大量引號與反引號時會解析失敗;改成先把腳本寫成檔案再執行

**驗證了什麼**

- 上線前先用線上文章頁實測 Google 翻譯代理:版面與樣式正常,內文、標題、目錄都有翻成英文
- build 無錯誤;產出的首頁含兩個翻譯連結,手機版選單也有;桌機導覽列截圖看得到 `Translate`

**還沒做 / 下次要做**

- [x] 上線後用截圖確認過:英文版文章頁、日文版首頁都正常,導覽列出現在 Google 工具列下方沒有被蓋住
- [ ] 日文版首頁截圖中,精選作品的那句簡介仍是中文(選單、標題、副標題都翻了)。可能只是 Google 還沒翻到,需要用真的瀏覽器再看一次
- [ ] 沒有實際「從選單點下去」測過,只測了連結的目的地;「翻的是當下那一頁」這段替換邏輯尚未在線上親手驗證
- [ ] 下拉選單打開的樣子沒有截圖確認(headless 無法模擬滑鼠懸停)
- [ ] 換自訂網域 `na23.dev` 時,`_config.fluid.yml` 那兩行連結的 `u=` 要一起改

- **內頁頂部**:同樣不放圖,只有標題;游標會留下褪色的字元軌跡。高度 45/40 → 35/30

**為什麼**

- **頂部不放整片 shader**:第一輪四個方向的大圖,使用者的評語是「很酷,但很花,而且意義不明」。所以改成先問「這塊的工作是什麼」:招牌的工作是說出站名,精選作品的工作是展示遊戲。已寫進 DESIGN.md 的設計原則與「明確不做的事」
- **招牌與精選作品上下並存**:招牌在頂部(身分),精選作品是內容區的第一塊(內容)。兩者各佔一個區域,不互相搶
- **深色用磷光、淺色用米色**:使用者兩個配色都喜歡,而網站本來就有深淺切換,不必二選一
- **封面維持彩色**:原本的提案是「平時暗、滑過才亮」,使用者認為彩色封面比較吸睛。改成「平時全彩,選到一張時其他張變暗」,保留點亮的感覺
- **`featured` 改了意思**:原本是「作品集裡加寬顯示」,但那會裁切封面所以一直沒用。現在是「放上首頁並排最前」,加寬的行為移除
- **只標了兩個個人作品為 featured**:這樣作品集的排列順序不會變
- **VT323 自己託管、只含英數**:不依賴外部字型服務;中文像素字型檔案以 MB 計,不載入
- **顏色放 CSS 變數、JS 去讀**:深淺兩套顏色只維護一個地方

**踩到的坑**

- Fluid 的 `theme_inject` 沒有首頁內容區的插入點,精選作品改用 `after_render:html` filter 插在主題輸出的隱藏 `<h1>` 前面。找不到時會印警告(已寫進 TECH.md)
- 主題把 banner 圖與遮罩寫在行內樣式,只能用 `!important` 蓋掉。副作用是各頁的 `banner_img` 設定全部失效
- 主題把副標題包在 `.h2` 裡,只縮小字級不改行高的話,320px 手機上換行後會往上壓到招牌
- 作品名稱加 `>` 前綴時,如果直接加在 flex 容器的 `::before`,會變成第三個 flex 項目把版面撐開;所以 `portfolio.js` 多包了一層 `.pf-name`
- headless Chrome 截圖時主題會依「現在幾點」決定深淺色,要用 `--blink-settings=preferredColorScheme=0/1` 指定
- headless Chrome 的 `--virtual-time-budget` 下,`requestAnimationFrame` 傳入的時間與 `performance.now()` 不同步,動畫進度要統一用後者算

**驗證了什麼**

- `hexo clean && hexo generate` 無錯誤、無警告;首頁 HTML 含精選作品區塊,其他頁面沒有
