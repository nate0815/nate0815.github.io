## 1. 這個網站是什麼

| 項目 | 內容 |
|---|---|
| 定位 | 個人網站 = 部落格 + 作品集 |
| 對外品牌 | **NA23** |
| 作者署名 | **Chiao** |
| 目前網址 | https://nate0815.github.io/ |
| 規劃網址 | `https://na23.dev`(尚未購買) |
| 語言 | 繁體中文(`zh-TW`)單語。**目前不做中英雙語。** |

### 內容類型

1. **讀書心得** — 遊戲設計、程式、雜食閱讀
2. **遊戲開發心得 / devlog** — 開發過程、技術筆記
3. **作品集** — 做過的遊戲與小工具,圖文為主

### 設計原則

- **內容優先**。版面服務內容,不喧賓奪主。
- **動態效果要有工作**。每個會動的東西都要答得出「它在告訴訪客什麼」;答不出來就不加。目前允許的只有三處(頂部招牌與軌跡、精選作品換圖、作品卡片點亮),規格見第 6 節「動態效果」。**文章內文區不放任何會動的東西。**
- **擴充一律走主題外部機制**。詳見 [TECH.md](TECH.md#擴充規則)。

## 2. 網址結構

| 路徑 | 用途 | 來源 |
|---|---|---|
| `/` | 首頁,文章列表 | 自動產生 |
| `/posts/<英文代號>/` | 單篇文章 | `source/_posts/*.md` |
| `/portfolio/` | 作品集 | `source/portfolio/index.md` + `source/_data/portfolio.yml` |
| `/about/` | 關於我 | `source/about/index.md` |
| `/archives/` | 文章封存 | 自動產生 |
| `/categories/` | 分類列表 | 自動產生 |
| `/tags/` | 標籤列表 | 自動產生 |
| `/404.html` | 404 頁 | 主題提供 |

**permalink 規則:`posts/:title/`**

`:title` 取自**檔名**,不是 frontmatter 的 `title`。因此:

- 檔名一律用**英文小寫加連字號**,例如 `combat-feel-tuning.md`
- 中文標題寫在 frontmatter 的 `title:` 欄位

> 為什麼:中文檔名會讓網址變成 percent-encoded 亂碼(`/posts/%E6%88%B0%E9%AC%A5.../`),既難分享也不利 SEO。

## 3. 導覽選單

順序即為 `_config.fluid.yml` 的 `navbar.menu` 設定:

`首頁` → `作品集` → `文章` → `分類` → `標籤` → `關於`

作品集排在文章之前,因為它是給「來看你能做什麼」的訪客看的,優先級高於瀏覽文章。

## 4. 分類與標籤

**分類(categories)** — 每篇文章**只給一個**,用來回答「這是哪一類內容」:

- `讀書心得`
- `遊戲開發`
- `雜記`

**標籤(tags)** — 想給幾個都行,用來標示具體主題:
`Unity`、`C#`、`遊戲設計`、`Game Jam`、`工具`……

> 原則:分類是**粗**的骨架,不要增生;標籤是**細**的索引,可以自由長。

## 5. 作品集規格

資料存放於 `source/_data/portfolio.yml`,由 `scripts/portfolio.js` 渲染為卡片網格。

### 欄位定義

| 欄位 | 必填 | 說明 |
|---|---|---|
| `title` | ✅ | 作品名稱 |
| `desc` | ✅ | **一句話**形容這個遊戲。不寫 jam 名稱、團隊人數、製作背景 |
| `cover` | | 封面圖路徑;留空則顯示漸層底色 + 作品名 |
| `year` | | 年份,顯示於卡片右上 |
| `role` | | 你在專案中的角色,只寫職務(例:`遊戲設計`) |
| `tags` | | **玩法**標籤陣列(解謎、平台跳躍…)。不放引擎、美術風格、jam 名稱 |
| `links` | | 按鈕陣列,每項含 `text` 與 `url` |
| `featured` | | `true` 則出現在首頁的「精選作品」輪播,並在作品集排最前。建議只給 2~3 個 |

> 原則:卡片是用來掃視的,字多會難讀。卡片只放「一句話 + 玩法標籤」,完整說明留給 itch.io 頁面或個別文章。

### 版面行為

- 網格採 `auto-fill, minmax(min(240px, 100%), 1fr)`,依螢幕寬度自動決定欄數,不需 media query;桌機三欄、平板兩欄、手機單欄
- 封面比例 **630:500**(itch.io 封面的原始比例),整張顯示不裁切,**一律以原本的彩色顯示**
- 「點亮」效果:滑鼠移到某張卡片時,它的邊框立刻亮起(深色模式是青綠光暈,淺色模式是紅色硬陰影並往左上浮起 3px),**其他卡片的封面同時變暗**;離開後用 1.2 秒慢慢恢復。僅限有滑鼠的裝置;用鍵盤 Tab 選到卡片內的按鈕時也會亮起
- 卡片是硬邊(無圓角)、2px 邊框。作品名稱用終端機字型,前面加 `>`
- 每張卡片的第一顆按鈕是主要動作,淺色模式下為紅底實心,其餘為外框

### 與文章的連結

作品若有對應的設計回顧文章,在該作品的 `links` 加一顆站內按鈕(例:`{ text: "設計過程", url: "/posts/afterglow-design-notes/" }`)。卡片本身不放長文。

### 排序

`featured` 為 `true` 者置頂,其餘維持 YAML 中的書寫順序。

### 首頁精選作品

`featured: true` 的作品會出現在首頁文章列表上方(只有第一頁),由 `scripts/home-feature.js` 產生。

- 左側:「精選作品」標籤、作品名稱、`desc`、兩顆按鈕(該作品 `links` 的第一項 +「全部作品」)、切換鈕 1、2、3…
- 右側:封面圖(630:500,彩色)。≤640px 時改為上圖下文
- 有兩個以上時每 7 秒自動換一個;訪客按過切換鈕後就不再自動換
- 只有一個精選作品時不顯示切換鈕、不輪播;一個都沒有時整個區塊不出現
- 沒有 JavaScript 時顯示第一個作品,連結照常可用

## 6. 視覺規格

| 項目 | 設定 |
|---|---|
| 主題 | Fluid,外觀以 `custom.css` 改成硬邊、終端機風格 |
| 深色模式 | 開啟,預設 `auto`(跟隨系統偏好) |
| 主題設定檔 | `_config.fluid.yml`(根目錄) |
| 自訂樣式 | `source/css/custom.css` |

### 配色

兩種模式共用同一套版面,只換顏色:

- **淺色模式 =「卡帶說明書」**:米色紙張、深藍硬邊、紅色重點。與 itch.io 個人頁(https://na23dev.itch.io/)同色系
- **深色模式 =「磷光螢幕」**:近黑底、琥珀色文字,重點色是青綠與橘。取自 AFTERGLOW 封面的配色

**磷光色只用在「框架」,不用在「閱讀區」。** 琥珀色的字放在導覽列、頂部標題、招牌、卡片這些字少的地方很好看,但整篇文章都是琥珀色會不耐看(同一個暖色調鋪滿畫面,眼睛沒有地方休息)。所以深色模式的內容區塊底色與內文都是**接近中性的灰**,只帶一點點暖;琥珀、青綠、橘只留給框架與重點。

主題本身的顏色設定在 `_config.fluid.yml` 的 `color:` 區塊;自訂元件(卡片、精選作品、字元 shader)的顏色在 `custom.css` 最上面的 `--na-*` 變數,**兩處都要同時有淺色與深色兩版**。

| 用途 | 淺色 | 深色 |
|---|---|---|
| 頁面背景、導覽列、頂部區塊 | `#f4f1de` 米色 | `#0d0b08` |
| 內容區塊背景 | `#fffdf5` | `#191816`(近中性) |
| 卡片背景 | `#fffdf5` | `#0d0b08` |
| 內文 | `#3d4059` | `#c9c5bc`(近中性,對比約 10:1) |
| 文章內的標題 | `#2f3247` | `#ece7db` |
| 內文連結 | `#c93a3a` | `#5ecfb1`(比重點色淡一階) |
| 導覽列文字、頂部標題 | `#3d4059` | `#f3d9a4` |
| 次要文字(引言、日期、摘要) | `#666982` | `#9d968a` |
| 框架上的次要文字(卡片、精選作品) | `#666982` | `#a88a55` 琥珀 |
| 重點色(連結、按鈕、點亮) | `#c93a3a` 紅 | `#3fe0b5` 青綠 |
| 第二重點色(小標籤、`>` 符號) | `#c93a3a` | `#ff8a3c` 橘 |
| 邊框、分隔線(硬邊) | `#4a4e69` 深藍 | `#3a2c14` |
| 內文分隔線 | `#e3dfc4` | `#33302a` |

淺色的連結色比 itch.io 的 `#dd4a4a` 略深,是為了讓內文連結在淺底上的對比度達到 4.5:1(`#dd4a4a` 只有 4.0:1,保留給懸停狀態)。

導覽列一律是實色加 2px 底線,不再是「透明、捲動後才上色」,因為頂部已經沒有圖片可以透。

### 深淺模式切換

訪客可以自己切換:導覽列最右邊的按鈕(桌機顯示圖示加「深色/淺色」文字,手機在展開的選單裡)。這是 Fluid 內建功能,選擇會記在訪客的瀏覽器裡。預設 `auto`,跟隨訪客系統的設定。

### 字型

| 用途 | 字型 |
|---|---|
| 內文、中文標題 | 主題預設(系統字型) |
| 站名、頂部標題、作品名稱、精選作品標題 | **VT323**(終端機風格的像素字型,SIL OFL 授權) |

VT323 的檔案放在 `source/asset/font/vt323-latin.woff2`(18 KB),不依賴外部字型服務。它**只涵蓋英數與標點**,中文會自動改用系統字型;`custom.css` 用 `size-adjust: 128%` 把它放大到與中文字等高。

**不載入中文像素字型**:檔案以 MB 計,會拖慢每一頁的載入。

### 頂部區塊

頂部**不放圖片**,底色與頁面相同。`custom.css` 會蓋掉主題的 banner 圖與遮罩,所以 frontmatter 的 `banner_img` 目前沒有作用。

- **首頁**:字元招牌。站名「`NA23.Chiao`」(網名與本名並列)由 `#` 字元排成的點陣字組成,中間的「.」用重點色。下方是打字機效果的副標題
- **其他頁面**:只有頁面標題,沒有招牌

要改招牌上的字,改 `source/js/na23.js` 最上面的 `SIGN_TEXT`;用到的每個字元都要在同一個檔案的 `FONT` 裡有 5×7 點陣圖。

### 動態效果

| 位置 | 效果 | 它的工作 |
|---|---|---|
| 首頁招牌 | 游標掃過的筆畫亮起再褪色(最亮 → 重點色 → 淡 → 熄滅,約 2 秒);沒人操作時一道光慢慢來回掃 | 讓站名是活的;「走過的地方會褪色」是 AFTERGLOW 的規則 |
| 其他頁面頂部 | 游標留下會褪色的字元軌跡;不動游標就什麼都沒有 | 與首頁維持同一個母題,但不干擾標題 |
| 精選作品 | 換作品時封面由左到右碎成字元再重組,約 1 秒;靜止時是一張乾淨的圖 | 提示「內容換了」 |
| 作品卡片 | 點亮(見第 5 節) | 讓人知道現在選到哪一張 |

共同規則:

- **尊重「減少動態效果」**:訪客的系統開了這個設定時,招牌是靜止的、沒有軌跡、精選作品不自動輪播且直接換圖、卡片沒有過場
- 捲出畫面就停止運算;沒有東西在變的時候不重畫
- 不引入任何外部函式庫,全部寫在 `source/js/na23.js`

### 頂部大圖高度

| 頁面 | 高度(螢幕高度的 %) |
|---|---|
| 首頁 | 60 |
| 文章、關於 | 35 |
| 作品集、封存、分類、標籤 | 30 |

手機另有上限,見下方「手機版」。

深色模式的樣式切換依賴 Fluid 在 `<html>` 加上的 `data-user-color-scheme="dark"`。自訂 CSS 若有顏色,**必須同時寫淺色與深色兩版**,用 CSS 變數管理(見 `custom.css` 底部)。

### 手機版

響應式版面由 Fluid 主題提供(選單收合成漢堡按鈕、內容單欄、文章目錄在窄螢幕隱藏),**不另外做手機專用版面**。`custom.css` 只補主題沒顧到的幾件事:

| 項目 | 規格 | 條件 |
|---|---|---|
| 頂部大圖高度 | 最高 `62vw`(390px 寬的手機約 240px) | 螢幕寬 ≤767px |
| 作品集卡片點亮效果 | 不套用 | 無滑鼠的裝置(`hover: hover` 不成立) |
| 作品集按鈕、精選作品切換鈕 | 高度至少 44px | 觸控裝置(`pointer: coarse`) |
| 首頁招牌 | 寬度為螢幕的 86%,字元自動變小 | 所有寬度(由 `na23.js` 依寬度計算) |
| 首頁副標題 | 字級縮到 0.8rem,維持一行 | 螢幕寬 ≤767px |
| 精選作品 | 上圖下文 | 螢幕寬 ≤640px |

驗收寬度:**390px**(主流手機)與 **320px**(最窄的常見手機),兩者都不得出現水平捲軸。

### 圖片資產

| 位置 | 用途 | 規則 |
|---|---|---|
| `asset/` | 原圖備份 | **不會發布到網站**。大尺寸原始檔放這裡 |
| `source/asset/default/` | 站台通用圖 | 頭像、favicon 等 |
| `source/asset/portfolio/` | 作品集封面 | 630×500(itch.io 封面原尺寸)或同比例,≤200 KB |
| `source/_posts/<文章名>/` | 單篇文章配圖 | 由 `post_asset_folder` 機制自動對應 |

#### 壓縮規格(硬性)

| 用途 | 尺寸 | 檔案大小上限 |
|---|---|---|
| 文章配圖 | 寬度 ≤1600px | **300 KB** |
| 作品集封面 | 630×500 或同比例 | **200 KB** |
| 頭像 `avatar.jpg` | 512×512 JPEG q86 | 目前 44 KB |
| favicon `favicon.png` | 180×180 | 目前 60 KB |

照片與遊戲截圖動輒數 MB,**進 `source/` 之前一定要壓**。含漸層或照片的圖優先用 JPEG(同畫質下比 PNG 小一個數量級);需要透明背景才用 PNG。

#### 圖片一律隨文章存放,不使用外部圖床

文章配圖**放在文章的同名資料夾裡**,Markdown 直接寫檔名:

```markdown
![調整前的打擊感](before.png)
```

❌ **不採用**「另開一個 public repo 放圖、用 `raw.githubusercontent.com` 外連」的做法。那是在沒有檔案空間的論壇(如巴哈姆特)才需要的變通方案,本站自己就是 host,沒有理由這樣做。理由:

1. **沒有好處** — 圖放另一個 repo 一樣是 GitHub 在服務、一樣計入同一份流量額度
2. **多一個會壞掉的環節** — 改檔名、刪檔、repo 轉 private 都會讓文章變破圖,而且 build 照樣成功、**不會有任何錯誤提示**
3. **本機預覽需要連網** — 目前 `hexo server` 完全離線可用
4. **文章不再自足** — 備份或搬家時圖片不會跟著走
5. **效能沒有比較好** — 實測 `raw.githubusercontent.com` 為 `Cache-Control: max-age=300`,GitHub Pages 為 `max-age=600`

#### 例外:這些情況才走外部

| 情況 | 做法 |
|---|---|
| 影片 | 上傳 YouTube 再嵌入。**影片檔絕不進 repo** |
| 簡報 | 每張投影片匯出成圖片(1280×720)放進文章資料夾,備註寫成內文;文章開頭附原始簡報連結。**不用 iframe 嵌入** |
| 多篇文章共用的圖 | 放 `source/asset/`,用 `/asset/xxx.png` 引用 |
| 超大檔案(遊戲下載、專案原始檔) | GitHub Releases 或 itch.io |

#### 流量與容量額度

GitHub Pages 官方限制:

| 項目 | 限制 |
|---|---|
| 發布後的站台大小 | **1 GB** |
| 每月流量 | **100 GB**(軟上限) |
| 原始碼 repo 建議大小 | 1 GB |
| 單次部署逾時 | 10 分鐘 |

換算感覺:一篇文章配 5 張壓縮過的圖(各 200 KB)約 1 MB,**寫一千篇才會碰到 1 GB**;每頁 2 MB 的話,要每月五萬次瀏覽才會碰到 100 GB。**前提是圖有壓縮**——20 MB 的原圖放五十張就吃光 1 GB。

> 註:「每小時 10 次 build」的限制不適用於本站,因為我們使用自訂 GitHub Actions workflow 部署。

`asset/`(原圖備份)雖然不發布,但仍計入 repo 大小。累積到約 100 MB 時應重新評估——改用 Git LFS,或原圖改放本機/雲端硬碟不進 repo。

## 8. 明確不做的事

記錄下來,避免日後重複討論:

| 項目 | 決定 | 理由 |
|---|---|---|
